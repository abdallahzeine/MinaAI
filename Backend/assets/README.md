# Reference Voice for Silma TTS

This directory holds the single reference voice that Silma clones on GPU `cuda:0`.

## Required files

- `reference.wav` — 8-second WAV file, 24 kHz, mono, containing the voice to clone. Must be <= 8.05 s (Silma will auto-trim if longer, but keep it ~8 s for best quality).
- `reference.txt` — exact verbatim transcript of `reference.wav`. Silma uses this for voice-conditioned diffusion; mismatch degrades quality.

Defaults expected by `main/core/tts.py`:

```
Backend/assets/reference.wav
Backend/assets/reference.txt
```

## Override via environment variables

Set either of these before starting Django to point elsewhere:

```
SILMA_REF_AUDIO=C:\path\to\your_voice.wav
SILMA_REF_TEXT=ويدقق النظر في القرآن الكريم ...
# OR
SILMA_REF_TEXT_FILE=C:\path\to\transcript.txt
```

## Replacing the placeholder

The current `reference.wav` is a silent 8 s placeholder generated by:

```
ffmpeg -y -f lavfi -i anullsrc=r=24000:cl=mono -t 8 -q:a 9 -acodec pcm_s16le Backend/assets/reference.wav
```

Replace it with a real recording:

1. Record exactly 8 seconds of clean speech (Arabic Fusha/MSA or English) at 24 kHz mono if possible — `ffmpeg` preprocessing will handle resampling.
2. Save as WAV (PCM 16-bit).
3. Write its exact transcript to `reference.txt` (Arabic diacritics optional — Silma’s Tashkeel model will enrich if missing, but providing fully diacritized Arabic gives precise pronunciation).
4. Restart Django: `python Backend/manage.py runserver 127.0.0.1:8000` — Silma stays warm in VRAM on `cuda:0`; no cold start.

## Verification

- Ensure `ffmpeg` is on PATH: `ffmpeg -version`
- Confirm both files are readable by the Django process
- Check logs at startup: `[TTS] Silma loaded on cuda:0 — warm in VRAM`
- Live test: use the mic, speak Arabic with diacritics and English; playback should follow the LLM reply in the cloned voice with lip-sync, and both models should stay on GPU (`nvidia-smi` shows ~6 GB total, no CPU offload).
